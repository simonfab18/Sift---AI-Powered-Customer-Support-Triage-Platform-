# Homepage and Product Experience Plan

**Product:** AI Customer Support Triage and Response System
**Working product name:** Sift
**Generated:** 2026-07-08
**Scope:** Public marketing homepage, onboarding entry, and authenticated Overview dashboard.

---

## 1. Homepage Objectives

The homepage must make the product understandable in a few seconds.

A visitor should quickly understand:

- What the product does
- Who it is for
- Why it is safer than fully autonomous AI support
- How Gmail integration works
- What the user receives after connecting an inbox
- Why the product can be trusted with customer support email
- What action to take next

### Primary message

> Turn your Gmail support inbox into an organized, AI-assisted ticket queue—while keeping a human in control of every reply.

### Primary audience

- Small and medium businesses using Gmail for support
- Founders answering support email themselves
- Small support teams that do not need a large enterprise helpdesk
- Agencies managing client support inboxes
- Operations teams that need triage, prioritization, and reply assistance

### Primary conversion

**Start free** or **Connect your support inbox**

For a portfolio or closed pilot version, use:

- **Request pilot access**
- **View product demo**
- **Sign in**

Do not advertise a free plan unless it actually exists.

# 7. How It Works

Use a five-step horizontal sequence on desktop and stacked sequence on mobile.

## Step 1 — Connect Gmail

```text
An owner or admin securely connects the support inbox through Google OAuth.
```

## Step 2 — New email becomes a ticket

```text
Matching messages are synchronized into the shared support queue.
```

## Step 3 — AI triages the request

```text
Sift identifies category, urgency, sentiment, a summary, and the recommended next action.
```

## Step 4 — An agent reviews the reply

```text
The team can edit, approve, or reject the AI-generated response.
```

## Step 5 — Create the Gmail draft

```text
Only an approved response can be placed into the original Gmail thread as a draft.
```

Add a small note:

```text
Manual sync and manual ticket controls remain available.
```

# 13. FAQ

Recommended questions:

### Does Sift send replies automatically?

No. In the first production version, an agent must approve a reply before Sift creates a Gmail draft.

### Does it replace Gmail?

No. Gmail remains the mailbox and final draft destination. Sift provides a shared triage and approval workspace.

### How do new emails appear?

After Gmail is connected, new matching mailbox changes are synchronized automatically. A manual Sync action remains available.

### Can multiple teammates use one workspace?

Yes. Workspaces support Owner, Admin, and Agent roles.

### What happens when AI is uncertain?

The system exposes confidence and can require human review. Agents can edit or reject every suggestion.

### Can I disconnect Gmail?

Yes. An owner or admin can disconnect the integration. The product should clearly explain what happens to previously imported ticket data.

### Does it read every email?

Import rules should determine which labels, senders, dates, or mailbox areas are synchronized. Explain the configured scope during onboarding.

### Can it send a reply directly?

Not in the first production release. The safe default is to create an approved Gmail draft.

# 16. Visual System

## Style direction

- Clean SaaS workspace
- Light neutral surfaces
- Strong whitespace
- Clear type hierarchy
- Subtle borders
- Soft shadows used sparingly
- Minimal decorative gradients
- Product UI as the main visual
- Teal as the primary action color
- Rose, amber, blue, and slate reserved for urgency

## Suggested color roles

```text
Primary / resolved action: teal
Critical: rose
High: amber
Medium: blue
Low: slate
Background: warm or cool off-white
Text: near-black neutral
Borders: low-contrast neutral
```

Urgency colors must not be reused randomly for marketing decoration.

## Typography

Use one strong sans-serif family with:

- Clear display weight for hero text
- Comfortable body text
- Tabular numbers for metrics
- Strong distinction between labels, values, and metadata
- Minimum 16 px body text on mobile

## Motion

Use motion to explain state changes:

- Ticket enters queue
- AI triage completes
- Approval changes state
- Draft confirmation appears

Avoid constant floating animation, excessive parallax, or motion that distracts from product meaning.

# 19. Homepage Performance Requirements

- Use optimized images
- Avoid autoplay video as the only product explanation
- Lazy-load content below the fold
- Keep the hero visual lightweight
- Avoid large client-side animation libraries when CSS is sufficient
- Track Core Web Vitals
- Use server-rendered marketing content where possible
- No blocking calls to authenticated product APIs on the public homepage

Suggested initial goals:

- Largest Contentful Paint under 2.5 seconds on a representative mobile connection
- Cumulative Layout Shift under 0.1
- Interaction to Next Paint under 200 ms for primary interactions

Treat these as engineering goals and measure them in production.

# 24. Dashboard Empty and Error States

## New workspace

Show a setup checklist:

1. Connect Gmail.
2. Configure import rules.
3. Run or wait for initial sync.
4. Invite a teammate.
5. Review the first triaged ticket.

## Gmail disconnected

Show one clear banner and a connect action. Do not display a misleading healthy dashboard.

## Sync degraded

Show:

- What failed
- Last successful sync
- Whether automatic retry is active
- Manual retry or reconnect action

## No tickets

Differentiate:

- Gmail not connected
- Initial sync in progress
- Import rules matched no messages
- Inbox is genuinely empty

## Metrics unavailable

Keep the rest of the page usable and show a localized retry action.
